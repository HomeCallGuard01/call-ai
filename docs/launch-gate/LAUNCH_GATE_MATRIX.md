# HCG Launch-Gate Matrix

**Status:** baseline assessment of `origin/main` eb43368, 2026-10-03, by the independent launch-gate reviewer (branch `test/launch-gate-adversarial`). Nothing here is merged, deployed, or applied.

**Principle.** HCG is not "safe to scale" because normal calls work. The gate is open only when no customer, attacker, routing loop, concurrent call pattern, compromised credential, technical failure or variable-cost path can create uncontrolled HCG financial exposure.

**Status vocabulary** (enforced by `tests/launch-gate/lib/status.mjs` and the self-test):

| status | meaning |
|---|---|
| PROVEN | Enforced control + strong evidence: a passing automated test that exercises the enforced control, a dated recorded manual execution (who/when/env/result), or a dated provider-config export. |
| PARTIAL | Some real protection exists, but either coverage is incomplete or evidence is weak (code inspection only). |
| UNPROVEN | No evidence either way, or the control does not exist yet and nothing currently creates exposure through it. |
| FAIL | A concrete gap exists on the baseline (usually demonstrated by an executable probe). |

**Never evidence of safety on their own:** "an alert is generated", "the dashboard shows red", "monitoring stops" (the PSTN leg can keep billing), "the provider probably blocks it", a design doc, or code inspection. The self-test rejects any PROVEN claim backed only by these.

**How statuses change.** Executable results can only *lower* a status (a FAIL probe forces FAIL); they never raise it. Promotion to PROVEN is a reviewed edit to `tests/launch-gate/registry.mjs` that adds strong evidence. A claim of FAIL whose probes all PASS is flagged "stale?" for re-assessment.

**Reproduce:** `node tests/launch-gate/run.mjs --markdown` (offline; no network, no .env, no database).
