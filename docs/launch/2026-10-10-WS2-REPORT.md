## A. Contract for WS3: customer allowance state (`GET /api/v1/me/allowance-state`)

- **Auth:** `requireAuthApi` + `requireEntitlement`, the same as `/api/v1/me/allowance`. The household always comes from the session; the route takes no parameters.
- **Router:** added to `routes/allowance.js`, which `server.js` already mounts. No `server.js` change is needed.
- **No £ figures are ever sent to the customer.** Only states, booleans and whole percentages. This matches the existing DT-2 rule: Fortress £ are HCG cost, not a customer price.
- **Unavailable is explicit.** If the state can't be read, `state` is `"unavailable"` and every boolean is `null`. A missing figure is never reported as protected.

### A.1 Response (HTTP 200)

```json
{
  "allowanceState": {
    "version": 1,
    "state": "normal",
    "percentUsed": 42,
    "screeningActive": true,
    "unknownCallersDelivered": true,
    "trustedCallersDelivered": true,
    "reserveRemaining": { "trustedPercent": 100, "unknownPercent": null },
    "serviceLimited": false,
    "periodStart": "2026-10-01T00:00:00.000Z",
    "resetsAt": "2026-11-01T00:00:00.000Z",
    "since": "2026-10-09T08:12:00.000Z",
    "thresholds": { "screeningLowPercent": 80, "continuityLowPercent": 80 },
    "lastRefusal": null
  }
}
```

| Field | Type | Meaning |
|---|---|---|
| `version` | `1` | Contract version. Any breaking change bumps it |
| `state` | enum, below | The household's deterministic allowance state |
| `percentUsed` | int 0–100 or `null` | Share of the period **screening budget** (plan budget + top-ups + adjustments) that is used or reserved by calls in progress. Reservations count as used, so this never understates use |
| `screeningActive` | bool or `null` | A new unknown call admitted now **would be screened** (stream, transcription, AI, warning SMS). False from `screening_paused` onwards |
| `unknownCallersDelivered` | bool or `null` | A new unknown caller would be **connected**, screened or not |
| `trustedCallersDelivered` | bool or `null` | A new trusted (contact) caller would be connected |
| `reserveRemaining.trustedPercent` | int 0–100 or `null` | Trusted continuity reserve left. `null` when the profile has none |
| `reserveRemaining.unknownPercent` | int 0–100 or `null` | Unscreened-delivery reserve for unknown callers left. `null` when the profile has none (the current default, see §C) |
| `serviceLimited` | bool | The service-wide emergency stop (kill switch or breaker) is engaged. New calls are refused for every customer |
| `periodStart`, `resetsAt` | ISO 8601 or `null` | The Fortress budget period |
| `since` | ISO 8601 or `null` | When the household entered `state` (from the transition log). `null` before the first transition is recorded |
| `thresholds` | object | The configured warning thresholds, so the app never hard-codes them |
| `lastRefusal` | `{ "reason": string, "at": ISO }` or `null` | The last call Fortress refused for this household this period. `reason` is a machine code (for example `household_budget_exhausted`, `household_hold`) |

### A.2 States (evaluated top to bottom; the first match wins)

| `state` | Condition (deterministic, SQL `fortress_household_allowance_state`) | Screening | Unknown callers | Trusted callers |
|---|---|---|---|---|
| `unavailable` | The state could not be read (DB down, migration missing, timeout) | `null` | `null` | `null` |
| `held` | A household financial hold is set (admin, fraud or automatic) | no | refused (busy) | refused (busy) |
| `hard_ceiling` | Screening budget can't fund a call, **and** neither continuity reserve can fund one | no | refused (busy) | refused (busy) |
| `continuity_low` | `continuity`, and ≥ `continuityLowPercent` of a continuity reserve that is in use is spent | no | per reserve | per reserve |
| `continuity` | The screening budget can no longer fund even an unscreened call. Calls continue only from the continuity reserves | no | only if the unknown reserve has room | only if the trusted reserve has room |
| `screening_paused` | The budget can't cover a new screened call's **worst case** (first lease + the full 30-minute monitoring window). Calls are still delivered, unscreened, from what is left of the budget | no | yes, unscreened | yes |
| `screening_low` | ≥ `screeningLowPercent` of the screening budget used or reserved | yes | yes | yes |
| `normal` | Otherwise | yes | yes | yes |

`serviceLimited: true` is reported alongside any state. It is not a state, because it is global and temporary.

### A.3 Ops events and push hooks

Each **transition** is recorded once, in the database, by `fortress_record_allowance_state(household, now)`:
- a row in `fortress_allowance_state_log`;
- an `fc_events` row, rule `allowance_state_changed`, with `{from, to, periodStart}`. The level is `info` (`normal`, `screening_low`), `warning` (`screening_paused`, `continuity`, `continuity_low`) or `critical` (`hard_ceiling`).

It runs after every authorisation and settlement, fire-and-forget (`services/containment/containment.js`). It never blocks or changes a call decision. The JS hook `onAllowanceStateChange({ householdId, from, to, state })` is where WS3 / ops attach push or ops-event delivery. **Event emission only. No SMS is sent.**

## B. Contract for WS4: per-household profitability (admin, read-only)

- **Router factory:** `routes/adminFinance.js` → `createAdminFinanceRouter({ loadProfitability, requireAuth, requireAdmin })`.
- **Not mounted.** The one-line mount for the lead is `app.use(require('./routes/adminFinance').createAdminFinanceRouter());`.
- **Every route is `requireAuth` + `requireAdmin` and GET only.** Nothing writes.

### B.1 Endpoints

| Method and path | Query | Returns |
|---|---|---|
| `GET /admin/api/finance/profitability` | `period=YYYY-MM` (UTC calendar month; default: current), `flag=<flag>` (optional filter), `limit` (1–500, default 100), `offset` | Portfolio object (B.2) |
| `GET /admin/api/finance/profitability/:householdId` | `period=YYYY-MM` | `{ version, generatedAt, period, assumptions, household: <row> }` |

```json

  "accountNumber": "HCG-000123 or null",

    "refundsGbp": 0.0,
    "netRevenueGbp": 4.53
  },
  "cost": {
    "fortressCommittedGbp": 1.10,
    "fortressReservedGbp": 0.07,
    "providerActualGbp": 0.80,
    "attributableUsageGbp": 1.10,
    "numberRentalGbp": 0.87,
    "fixedAllocationGbp": 0.25,
    "totalGbp": 2.22
  },
  "contribution": { "gbp": 2.31, "marginPct": 51.0 },
  "projection": { "projectedUsageGbp": 3.55, "projectedTotalCostGbp": 4.67, "projectedContributionGbp": -0.14 },
  "allowance": {
    "state": "screening_low",
    "percentUsed": 81,
    "budgetGbp": 3.0,
    "topUpCreditGbp": 0.0,
    "budgetRemainingGbp": 0.57,
    "trustedReserveRemainingGbp": 0.5,
    "unknownReserveRemainingGbp": 0.0,
    "held": false
  },
  "flags": ["projected_loss"]
}
```

Notes:
- `revenue.counted` is false (with `reasonNotCounted`) for: sandbox or test purchases (`sandbox`), complimentary, staff or partner (`complimentary`), no entitlement (`no_entitlement`), and a Stripe price that is not in the configured live price map (`unknown_price`). Uncounted revenue is £0, never a guess.
- **VAT is removed** at the configured rate. **Store fees** use the channel's fee model: Stripe 1.5% + 20p + Billing 0.7% + Tax 0.5%; Google 15%; Apple 30% unless `FINANCE_APPLE_FEE_MODEL=store15`.
- `attributableUsageGbp` uses the Fortress committed figure. It is conservative: Fortress charges max(estimate × 1.1 uplift, provider actual). `providerActualGbp` is shown beside it and lags by the provider billing delay.
- `numberRentalGbp` is charged per held number per month. `fixedAllocationGbp` is the register's infrastructure allocation.
- Flags: `heavy_user`, `loss_making`, `projected_loss`, `held`, `hard_ceiling`, `actual_exceeds_estimate`, `revenue_not_counted`, `reconciliation_gap`.
