## Assumed allowance contract (for the lead to reconcile with WS2)

```
GET /api/v1/me/dashboard
  allowanceState?: {                      // also accepted at customerAllowance.allowanceState
    version?: 1,                          // anything other than 1 (or absent) → ignored
    state: "normal" | "screening_low" | "screening_paused" | "continuity_low" | "hard_ceiling",
    percentUsed: number | null,           // 0–100, clamped
    screeningActive: boolean | null,      // true only when unknown callers are being checked NOW
    resetsAt?: string | null,             // ISO; shown as "1 November"
    trustedCallersContinue?: boolean | null // hard_ceiling: trusted callers still connect
  }
```

Meanings assumed:
- `screening_low`: still checking, getting close to the limit.
- `screening_paused`: no checking; calls still delivered.
- `continuity_low`: no checking, and calls may soon stop being delivered.
- `hard_ceiling`: forwarded calls may not be delivered.

**Parser rules** (`mobile/lib/allowanceState.ts`):
- A missing or malformed field leaves the screen exactly as it was before.
- An unknown `state` is ignored unless `screeningActive === false`, in which case the app shows generic "not being checked" wording.
- `normal` or `screening_low` together with `screeningActive === false` is read as "unknown" (the less reassuring reading).
- `mobile/lib/types.ts` is not WS3-owned, so the field is read untyped. The lead may add `allowanceState?: unknown` to `DashboardResponse`.

## Risks

- **H5 is not device-proven.** If Android does not launch or foreground HCG after a killed-app answer, recovery happens when the customer opens HCG (W1 checks this).
- `getCalls()` creates a second JS `Call` per native call. Events fan out by UUID, which is harmless.
- The `##21#` fallback is unconfirmed per network. The caveat says so, and the customer sees the carrier's reply.
- Under `**21*`, return-to-normal is **never automatic**. It becomes automatic only under the untested SILENCE + CFNRy architecture (roadmap §4).
