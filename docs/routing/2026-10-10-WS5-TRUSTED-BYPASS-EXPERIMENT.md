### 1.2 What this means
- **Typical household: usage £2.08 → £0.76 (−£1.32/month), margin 26% → 52% on Stripe (18% → 44% on Play 15%).** It clears the 40% target on both channels.
- **Trusted cost stops depending on how long people talk** (checked: 5,000 trusted minutes cost the same as 150). The uncapped trusted-minute exposure (conflict C1 in the WS2 report) disappears for bypass customers.

Very heavy households stay loss-making because of 200 monitored unknown minutes; that is an allowance question, not a trusted-call one.
- **Scope:** only Android customers on a carrier where both tests pass. iPhone customers, customers on carriers that refuse CFNRy to an HCG number (or have no MMI, e.g. Three/giffgaff by code), and everyone until the build ships stay on today's column.

- **Production-safety gate first:** `*#21#`, `*#61#`, `*#62#`, `*#67#`, `*#43#` read and recorded. If always-forward is on (to the Motorola's production HCG number), it is deactivated with `#21#` (never `##21#`/`##002#`) and re-registered to the recorded number at the end.
- **Install:** archived v0.3 only, after `shasum -a 256 -c`; `adb install ~/hcg-android-probe/v0.3/hcg-divert-probe.apk`; role granted through the probe's own button; `dumpsys role` cross-check; gate S3 (SDK ≥ 30, else stop for the v0.3.1 approval).
- **Calls:** (1) baseline, probe observe → voicemail at N s; (2) trusted contact → rings natively, no log line; (3) ★ unknown → silent, voicemail at N ± 3 s, ×3; (3w) withheld → rings; (4) call waiting; (5) locked; (6) force-stopped / role removed → never busy; (7) DND. Timings T0–T3 and `respondedIn` per call; logcat (main/system/radio/events) for the session plus `dumpsys telecom` per call; Motorola `screenrecord` and iPhone screen recording.
- **Stop rules** include any HCG involvement, any busy on a trusted call, >25 calls or >90 minutes.
- **Restore** (10 ticked steps) ends with all five interrogation codes equal to the gates.
- **Approvals A-1..A-5.** **About 75–90 minutes. Cost £0.**

### 5.2 Behaviour and failure modes

| Situation | Behaviour | Customer-visible |
|---|---|---|
| Process death, OOM, force-stop | Telecom binds the role holder per call (Test A step 6 checks). If binding fails or the app is gone → call rings normally | Fail-**open** (reachable, unscreened). Cost-safe: HCG never sees the call |
| 5 s timeout, exception, missing list | ALLOW | Rings normally |
| Battery optimisation / app standby | Binding is by Telecom, not the app's own scheduling; mode refresh may lag, which only delays turning silencing off/on | Request "Unrestricted" battery in setup on OEMs known to kill services (Samsung, Xiaomi) |
| Call waiting | Silenced waiting call stays unanswered → CFNRy (if CW on) or CFB via network-determined busy (if CW off) | Test A step 4; set CFB to HCG too, or leave it at voicemail (decision) |
| Locked screen | Same as unlocked (Telecom path is unchanged) | Test A step 5 |
| DND | Ringer suppressed for everyone outside the DND exceptions; network still alerting → CFNRy diverts suppressed trusted calls too (leakage) | Copy: "with Do Not Disturb on, any call DND silences (even a contact) goes to HCG after the timer" |
| Dual-SIM | The service sees `getAccountHandle()`; CFNRy is per-SIM | Silence only calls on the protected SIM's `PhoneAccountHandle`; ALLOW the other SIM |
| Withheld / restricted | Android 11+ never asks the service → rings natively (unscreened). Android 10 passes an empty number → ALLOW | Known gap, stated in copy |
| Spoofed trusted CLI | Rings natively (as a trusted call would under any scheme) | Same as today's trusted-list risk |
| Customer misses a trusted call | CFNRy → HCG → leakage treatment (TB-3), not carrier voicemail | Copy; option to keep a voicemail-like message |
| Customer answers a silenced unknown call | Allowed: they can see it | £0 to HCG |

Android 12–15: no documented change to the silence path found in the sources read; must be in the device matrix (Pixel and Samsung on 14/15).

### 5.4 Play policy
- `ROLE_CALL_SCREENING` is a role, not a restricted permission; HCG needs **no** `READ_CALL_LOG`/`READ_PHONE_STATE`/`ANSWER_PHONE_CALLS` for this. No Permissions Declaration Form for call log/SMS is triggered. *Re-check the live "Permissions and APIs that access sensitive information" page before submission (WS5 could not confirm its current wording).*
- `READ_CONTACTS` (already declared): Play Console declaration prompts started Sept 2026; mandatory for apps targeting API 37+ (enforcement 27 Jan 2027). Call screening ("identify, block or filter incoming calls") is a listed use case (N2). Needs prominent disclosure, Data safety entry ("contacts processed on device for call routing; trusted list sent to HCG") and privacy-policy wording.
- No new payment surface; does not change the Play Billing question.

### 5.5 iPhone status
No API can silence, reject or route a cellular call. The only candidate is Apple *Silence Unknown Callers* + Live Voicemail **off** + conditional forwarding (Candidate A, `IP/.../REPORT.md`), relying on undocumented behaviour; **T4 is untested**. Even if T4 passes, allowance exhaustion cannot become automatic on iPhone (the app cannot switch Silence off), Three/giffgaff iPhones cannot set CFNRy by code, and Apple decides who is "known". iPhone stays on `**21*`; T4 Phase 1 (`IP/.../TEST_CHECKLIST_PHASE1.md`, £0, Motorola as caller) can run in the same session as Test A with roles swapped, under its own approval.

## 7. Honest limits
- Every bypass figure in §1 is conditional on Test A and Test B passing, and then only per carrier and handset.
- One Lebara/Motorola pass says nothing about other networks; the Vodafone PAYG and Three restrictions already show it will not be universal.
- Fail-open changes the promise: an HCG failure means unknown callers ring unscreened, not that calls stop.
- Withheld callers are never screened on Android 11+.
- Nothing here was run on a device; no forwarding, Twilio, staging or production state was read or changed by WS5.
