## Rollback reference

- `supabase/migrations/_rollbacks/021_rollback_household_activation_verified.sql` — drops `mark_household_activation_verified(uuid)`, then drops `activation_verified_at`. Safe today (no real customer activation timestamp exists yet — the mobile app that would create one isn't deployed); becomes progressively less safe to run casually once real customer data exists there.
- `supabase/migrations/_rollbacks/022_rollback_lock_down_security_definer_execute_grants.sql` — re-grants `anon`/`authenticated` `EXECUTE` on all 11 functions and restores the permissive default privileges. Reversing this recreates the exposure 022 exists to close — only appropriate if 022 itself is found to be wrong, not as a routine undo.
- Project convention (unchanged by this release): prefer a new forward-fixing migration over running a rollback where avoidable.
