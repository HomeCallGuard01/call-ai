### 3.1 Which backend a TestFlight build talks to

TestFlight / production-profile builds call the **production** backend (`eb43368`). Production already sends:
- `steps`
- `guidance`
- `recentDeliveryProblem`
- the four protection booleans

It does **not** yet send:
- `activationStage` / `protectionBlockers`
- `customerAllowance`
- `account.accountNumber`

So a 1.0.2 TestFlight build used today runs the app's **tested older-backend fallback**. It is never more optimistic than before, and the incident shape still shows **PROTECTION NEEDS ATTENTION**. Three things only appear once the candidate backend and migrations 062/067 are in production, or in a staging-pinned iOS build:
- per-stage wording (hold, number conflict, old number, number failed)
- the account number
- the allowance

The EAS staging profile is uncommitted (staging-readiness doc).

## 5. £4.99 → £5.99 price inventory (Task 7)

**Decision recorded:** launch price £5.99/month including VAT. **Not applied to any live provider or store.**

**Key fact:** the 1.0.2 app contains **no price figure at all**. iOS shows StoreKit's price, Android the server's Stripe offer, and Membership the server's `priceLabel`. So the app moves to £5.99 **automatically and simultaneously** with the provider change. It can never claim £5.99 while checkout charges £4.99. `tests/subscription-price-display.test.mjs` §5 asserts that no customer-facing mobile or server source contains a hard-coded £ amount.
